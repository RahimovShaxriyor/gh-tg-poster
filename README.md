# Панель анонсов из коммитов (GitHub → ИИ → Telegram)

Веб-панель для автоматического создания и публикации постов в Telegram-канал на основе коммитов в GitHub с помощью нейросетей (Anthropic Claude или OpenAI ChatGPT).

---

## Возможности
- **Опрос без вебхуков**: сервер периодически опрашивает GitHub API (настраиваемый интервал 1–60 минут), внешние вебхуки настраивать не нужно.
- **Умный debounce**: серия коммитов объединяется в один общий пост после паузы затишья.
- **Фильтрация шума**: служебные файлы (lock-файлы, `.env`, сборки, изображения) отсекаются из diff, чтобы нейросеть фокусировалась только на сути изменений.
- **Три режима работы**:
  - `Черновик (approve)`: пост создаётся как черновик, вы проверяете его, при желании редактируете и публикуете в один клик.
  - `Автоматически (auto)`: пост сразу отправляется в Telegram-канал.
  - `Ежедневный дайджест (digest)`: раз в сутки в заданное время и часовой пояс собираются все изменения за день в один пост.
- **Шифрование секретов в базе данных**: при указании ключа `ENCRYPTION_KEY` все токены шифруются алгоритмом AES-256-GCM.
- **Встроенные проверки подключений**: прямо из панели можно протестировать доступ к GitHub, права бота в канале Telegram и ответ нейросети.
- **Защита и надёжность**: атомарная отправка постов (защита от двойной публикации), ограничение частоты попыток входа (защита от перебора пароля), заголовки безопасности (CSP, nosniff, DENY framing), автоматический healthcheck.

## Пошаговое развертывание на AWS EC2

### 1. Создание виртуального сервера EC2
1. Войдите в консоль AWS и перейдите в раздел **EC2** → **Launch Instance**.
2. Выберите операционную систему: **Ubuntu 24.04 LTS (x86_64)**.
3. Тип инстанса: **t3.micro** (достаточно для работы, входит в Free Tier).
4. Ключевая пара (Key pair): создайте или выберите существующий `.pem` ключ для входа по SSH.
5. Настройки сети (Security Group):
   - **SSH (порт 22)**: разрешите доступ только с вашего IP-адреса (`My IP`).
   - **HTTP (порт 80)**: разрешите доступ для всех (`0.0.0.0/0`) — требуется Caddy для выпуска SSL-сертификата.
   - **HTTPS (порт 443)**: разрешите доступ для всех (`0.0.0.0/0`) — для безопасного входа в веб-панель.
6. Диск (EBS): 15–20 ГБ gp3. Нажмите **Launch Instance**.

### 2. Привязка Elastic IP и домена
1. В левом меню AWS EC2 откройте **Network & Security** → **Elastic IPs**.
2. Нажмите **Allocate Elastic IP address**, затем выберите его и нажмите **Actions** → **Associate Elastic IP address**.
3. Привяжите адрес к созданному серверу.
4. В панели управления вашим доменом (Cloudflare, Reg.ru, Namecheap и т.п.) добавьте **A-запись**, указывающую на этот Elastic IP (например, `poster.yourdomain.com`).
> **Важно**: Без домена и HTTPS браузер не сможет безопасно передавать пароль администратора.

### 3. Установка Docker на сервере
Подключитесь к серверу по SSH:
```bash
ssh -i /path/to/key.pem ubuntu@ВАШ_ELASTIC_IP
```

Установите Docker и Docker Compose официальным скриптом:
```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker ubuntu
# Перезайдите в SSH-сессию, чтобы применились права группы docker
exit
```

### 4. Копирование проекта и запуск
Подключитесь снова и загрузите проект (или клонируйте репозиторий):
```bash
git clone <URL_РЕПОЗИТОРИЯ> gh-tg-web
cd gh-tg-web
```

Создайте файл `.env` на основе примера:
```bash
cp .env.example .env
nano .env
```

Заполните переменные:
- `ADMIN_PASSWORD`: сложный пароль для входа в веб-панель.
- `SESSION_SECRET`: длинная случайная строка (минимум 32 символа) для подписи сессий.
- `ENCRYPTION_KEY`: случайный ключ для шифрования токенов в SQLite (например, результат `openssl rand -hex 32`).
- `DOMAIN`: ваш поддомен (например, `poster.yourdomain.com`).

Запустите контейнеры:
```bash
docker compose up -d --build
```

Caddy автоматически получит бесплатный TLS-сертификат от Let's Encrypt, настроит HTTPS и перенаправит трафик на приложение.

Откройте в браузере: `https://poster.yourdomain.com`.

## Настройка в веб-панели

1. **Вход**: введите пароль администратора из переменной `ADMIN_PASSWORD`.
2. **Подключение GitHub через GitHub App (основной способ)**:
   Подключение через собственное приложение GitHub App не требует ручного создания и обновления персональных токенов, а доступ к репозиториям настраивается прямо в интерфейсе GitHub.

   #### Пошаговая регистрация GitHub App:
   1. Откройте [GitHub Settings → Developer settings → GitHub Apps → New GitHub App](https://github.com/settings/apps/new).
   2. Заполните поля формы:
      - **GitHub App name**: любое уникальное имя (например, `gh-tg-poster-yourname`).
      - **Homepage URL**: URL вашей панели, например `https://poster.yourdomain.com`.
      - **Identifying and authorizing users**:
        - Оставьте Callback URL пустым (авторизация пользователей не требуется).
      - **Post installation**:
        - **Setup URL**: `https://poster.yourdomain.com/auth/github/setup`
        - Включите чекбокс **Redirect on update** (перенаправлять в панель после изменения списка доступных репозиториев).
      - **Webhook**:
        - Снимите отметку **Active** (Webhook выключен, сервер опрашивает API самостоятельно).
      - **Permissions** → **Repository permissions**:
        - **Contents**: выберите **Read-only** (для чтения коммитов и diff файлов).
        - *(Metadata: Read-only выставится автоматически)*.
      - **Where can this GitHub App be installed?**:
        - Выберите: **Only on this account**.
   3. Нажмите **Create GitHub App**.
   4. **Где взять App ID и App Slug**:
      - На открывшейся странице приложения в блоке **About**:
        - Скопируйте **App ID** (число, например `123456`) в переменную `GITHUB_APP_ID`.
        - Скопируйте **App Slug** (slug из публичной ссылки на приложение вида `https://github.com/apps/<app-slug>`) в переменную `GITHUB_APP_SLUG`.
   5. **Генерация и экспорт приватного ключа (.pem)**:
      - Внизу страницы в блоке **Private keys** нажмите **Generate a private key**.
      - Браузер скачает файл `.pem` (например, `app-name.2026-10-22.private-key.pem`).
      - Преобразуйте файл ключа в base64 в одну строку:
        - **Linux / macOS**:
          ```bash
          base64 -w0 key.pem
          ```
        - **Windows PowerShell**:
          ```powershell
          [Convert]::ToBase64String([IO.File]::ReadAllBytes("key.pem"))
          ```
      - Скопируйте полученную строку в переменную `GITHUB_APP_PRIVATE_KEY_B64` в `.env`.
      - *(Альтернатива)*: скопируйте `.pem` файл на сервер и укажите путь к нему в `GITHUB_APP_PRIVATE_KEY_PATH=/path/to/key.pem`.
   6. Перезапустите контейнер:
      ```bash
      docker compose up -d
      ```
   7. В веб-панели перейдите в **Настройки → GitHub** и нажмите **«Подключить GitHub»**. Выберите репозитории, к которым разрешён доступ, и подтвердите установку. После возврата в панель вы увидите зелёный статус «Подключено» и список доступных репозиториев в выпадающем списке.

   #### Запасной вариант: Персональный токен (Personal Access Token)
   Если вы не хотите создавать GitHub App, в разделе настроек GitHub раскройте **«Подключить вручную токеном»**:
   - Перейдите в [Personal access tokens → Fine-grained tokens](https://github.com/settings/personal-access-tokens).
   - Выберите права `Contents: Read-only` и `Metadata: Read-only`.
   - Вставьте токен в поле и нажмите **«Сохранить»**.
3. **Telegram**:
   - Напишите боту `@BotFather` команду `/newbot` и получите токен.
   - Вставьте токен в панели.
   - Добавьте созданного бота в ваш канал в качестве **Администратора** с правом публикации сообщений.
   - Укажите `@username_канала` или числовой ID канала.
   - Нажмите **«Проверить Telegram»**, а затем **«Отправить тестовый пост»**.
   - **Владелец бота** (для черновиков с кнопками в личку): нажмите **«Получить код»** и отправьте боту в личные сообщения `/start <код>`. Код одноразовый и действует 15 минут. Без кода бот никого владельцем не назначает.
   - Если поле канала пустое, канал привяжется автоматически, но только когда бота добавит администратором уже привязанный владелец.
4. **Нейросеть (ИИ)**:
   - Выберите провайдера: **Anthropic (Claude)** или **OpenAI (ChatGPT)**.
   - Вставьте API-ключ и название модели (например, `claude-sonnet-5-5` или `gpt-4o-mini`).
   - Нажмите **«Проверить ИИ»**, чтобы убедиться в доступности API.
5. **Поведение**:
   - Выберите режим публикации: `Черновик`, `Автоматически` или `Ежедневный дайджест`.
   - Нажмите **«Сохранить настройки»**.

## Обновление и откат

### Обновление до новой версии:
```bash
cd ~/gh-tg-web
git pull origin main
docker compose up -d --build
```
Все данные и настройки сохраняются в директории `./data/app.db` и не стираются при пересборке.

### Откат на предыдущую версию:
```bash
cd ~/gh-tg-web
git log -n 5 --oneline
git checkout <ХЭШ_ПРЕДЫДУЩЕГО_КОММИТА>
docker compose up -d --build
```

## Резервное копирование по расписанию (Cron)

В проект входит скрипт горячего резервного копирования `scripts/backup.sh`. Он безопасно копирует базу `data/app.db` в каталог `backups/` с датой и автоматически удаляет копии старше 14 дней.

Сделайте скрипт исполняемым:
```bash
chmod +x scripts/backup.sh
```

Добавьте задачу в cron для ежедневного запуска в 03:00 ночи:
```bash
crontab -e
```
Добавьте строку в конец файла:
```cron
0 3 * * * /home/ubuntu/gh-tg-web/scripts/backup.sh >> /home/ubuntu/gh-tg-web/backups/backup.log 2>&1
```

## Решение типичных ошибок

### 1. Ошибка GitHub 401 или 404
- **401 Unauthorized**: токен GitHub истёк или введён с ошибкой. Сгенерируйте новый токен в настройках GitHub и обновите его в панели.
- **404 Not Found**: токен не имеет доступа к выбранному репозиторию (проверьте в настройках fine-grained токена список разрешённых репозиториев) либо репозиторий является приватным, а токен создан без прав на приватные репозитории.

### 2. Ошибка Telegram «Bad Request: chat not found» или ошибка публикации
- Бот ещё не добавлен в канал. Откройте настройки канала в Telegram → **Администраторы** → **Добавить администратора** → найдите вашего бота.
- Убедитесь, что у бота включено право **«Публикация сообщений» (Post Messages)**.
- Если канал публичный, убедитесь, что имя указано через `@` (например, `@my_channel`). Если приватный — дождитесь, пока бот сам определит числовой ID канала после назначения админом, либо узнайте ID вручную.

### 3. Ошибка Caddy: SSL-сертификат не выпускается
- Проверьте, что домен действительно указывает на IP вашего сервера: `nslookup ваш-домен.com`.
- Проверьте в AWS Security Group, что порт **80 TCP** открыт для всего мира (`0.0.0.0/0`). Центр сертификации Let's Encrypt выполняет проверку владения доменом именно по порту 80 (HTTP-01 challenge).
- Проверьте логи Caddy:
  ```bash
  docker compose logs caddy
  ```
- Если домен привязан только что, подождите 5–10 минут, пока обновятся DNS-записи по всему миру.

### 4. Просмотр логов приложения
```bash
# Логи приложения в реальном времени
docker compose logs -f app

# Проверка статуса контейнеров
docker compose ps
```
